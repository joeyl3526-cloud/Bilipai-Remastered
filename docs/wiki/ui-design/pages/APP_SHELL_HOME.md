## 初学者解释

应用外壳是全局“房屋结构”，首页是外壳中的一个内容目的地。两者看起来经常同时出现，但所有权不同：外壳管理主导航和跨页面区域，首页管理推荐内容、分类入口与刷新。把二者混在一起会导致首页重组时连全局播放器或底栏一起重建。

## 规范要求

- 主导航、全局 inset、迷你播放器和 Navigation 3 内容只由外壳拥有。
- 首页保持内容优先，顶部工具和推荐卡不做营销式大 Hero，也不把普通区块全部做成浮动卡。
- 主目的地切换保留各自滚动状态；重复点击当前首页可以执行回顶，但不得重复压栈。

<a id="p001"></a>
## P001 主应用容器档案

- **用户目标**：在首页、动态、历史、听视频、个人等主目的地间稳定切换，同时不中断合理的全局播放状态。
- **入口与出口**：冷启动通常进入本容器；首次引导或直达 Story 是例外。出口为各主目的地和压入的详情页，根返回按 Android 约定退出或交给系统。
- **信息层级**：当前主内容 > 全局播放状态 > 主导航 > 次要全局提示。容器自身不显示业务标题。
- **文字线框**：`系统栏 /（可选顶部层）/ 主内容 Pager / 迷你播放器 / 底栏`；Expanded 为 `Rail / 主内容 / 可选迷你播放器`。
- **设备适配**：Compact 使用底栏；Medium/Expanded 可按设置使用 Rail/Sidebar；切换宽度时保留选中目的地和各页位置。
- **组件清单**：`AppScaffold`、`AppBottomNavigationHost`、`AppNavigationBar`、`AppPlatformNavigationRail`、`HorizontalPager`、`MiniPlayerOverlay`、SnackbarHost。
- **状态矩阵**：首次加载=显示外壳并让子页加载；刷新=交给当前子页；正常=单一当前目的地；部分数据=全局区与子页独立；空/失败/离线=由子页或全局服务局部表示；未登录=可浏览公开主目的地；权限不足=仅受影响能力降级；禁用=隐藏或标明不可用目的地；分页加载/结束=交给子页。
- **交互和返回**：底栏/侧栏只切换主目的地，不重复 push；系统、预测与顶部返回最终结果一致；子详情先弹出，根容器不拦截应由系统处理的退出。
- **权限/登录**：外壳不得在启动时无条件索取权限；登录仅影响特定目的地内容，不阻塞公开首页。
- **性能**：Pager 预加载有上限；不可因底栏动画重组所有页面；视频卡返回快照和播放器 session 只有一个所有者。
- **无障碍**：导航项读出名称、选中和角标；切换后焦点进入新主内容标题；底栏与 Rail 不同时暴露。
- **当前差距**：BottomBar、TopBar 与设置侧栏仍在演进；不同 inset 与玻璃模式组合需要矩阵验证。
- **验收**：连续切换所有可见目的地两轮，打开/关闭迷你播放器并旋转；预期无双导航、遮挡、重复压栈或播放反向触发。

<a id="p002"></a>
## P002 首页档案

- **用户目标**：快速发现推荐视频、直播、番剧、分区和个人常用入口，并能刷新或继续上次浏览。
- **入口与出口**：由主容器首页目的地进入；可去搜索、登录/个人、设置、动态、历史、分区、直播、番剧、分类、收藏、下载、消息、Story、用户空间和各内容详情。
- **信息层级**：顶部身份/搜索和必要快捷操作 > 当前首页分类/推荐流 > 单张内容卡标题与作者/统计 > 次要工具。
- **文字线框**：`顶部控制 / 分类或 Tab / 可选横向重点内容 / 推荐列表或网格 / 刷新与分页状态`。
- **设备适配**：360dp 保证卡片标题与统计不互相覆盖；约 700dp 增加合理列数；Expanded 限制单卡宽度并利用网格，不把封面横向拉伸。
- **组件清单**：`AppTopBar`/首页专用 top chrome、`AppSearchEntry`、`AppScrollableTabRow`、`AdaptivePullToRefreshBox`、视频/直播卡、`ContentCardSurfacePolicy`、共享加载/错误目标组件。
- **状态矩阵**：首次加载=与真实卡尺寸一致的稳定占位；刷新=保留旧流并显示顶部进度；正常=推荐内容可滚动；部分数据=局部区块隐藏或提示；空内容=说明暂时无推荐并可刷新；失败=显示原因和重试；离线=保留缓存并标明受限；未登录=公开推荐+登录入口；权限不足=不影响基础浏览；禁用=不可用快捷入口有原因；分页加载=尾部轻量进度；分页结束=稳定到底提示或自然结束。
- **交互和返回**：下拉刷新不与顶部栏/横向卡冲突；整卡点击进入详情，内部菜单不触发整卡；从详情返回尽量恢复来源卡附近与滚动位置。
- **权限/登录**：未登录不弹强制登录；收藏、历史等需要账号的动作在触发时解释并导向登录。
- **性能**：Lazy 列表使用稳定 key；图片按显示尺寸加载；组合期不做网络/重计算；玻璃效果可按设备档位降级。
- **无障碍**：卡片合并标题、作者、统计与进度，菜单单独聚焦；刷新状态不过度播报；首页分类读出选中状态。
- **当前差距**：首页拥有多种卡片样式和局部 motion policy，媒体比例、标题行数与卡面入口尚未完全统一。
- **验收**：在 360/700/1000dp、Miuix 明暗/AMOLED 下刷新并滚动 3 屏，打开视频后返回；预期无空白跳动、key 崩溃、卡片拉伸或位置异常。

## Compose 短示例

```kotlin
HomeScreen(
    viewModel = homeViewModel,
    onVideoClick = onVideoClick,
    onSearchClick = onSearchClick
)
```

Screen 负责业务编排，卡片只接收内容状态与点击事件。

## 代码映射

- 外壳渲染：`AppNavigation.kt` 的 `MAIN_HOST` 分支
- 首页：`feature/home/HomeScreen.kt`
- 顶栏/底栏：`feature/home/components/TopBar.kt`、`BottomBar.kt`
- 刷新：`HomeRefreshIndicator.kt` 与自适应 PullToRefresh

## 当前差距

本文件定义目标合同，不改变正在修改的 TopBar/BottomBar。首页多卡片实现和效果策略需在后续任务按性能与语义逐项收口。

## 验收方法

除两个档案各自步骤外，验证主容器切换不会重置首页列表，首页错误/离线不会遮掉全局导航或停止仍应继续的播放 session。
