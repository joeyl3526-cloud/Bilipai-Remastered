## 初学者解释

规范描述“应该到哪里”，台账描述“现在离那里多远”。差距不是立即改代码的授权，而是后续工作可以直接领取的任务卡。每张卡要说明证据、影响、入口和验收，避免只写“UI 不统一”。

## 规范要求

所有差异必须按本页模板记录证据、目标、风险、步骤和验收；不得用含糊描述代替任务卡，也不得把未实施目标标为已完成。

## 优先级

| 优先级 | 含义 | 示例 |
|---|---|---|
| P0 | 阻塞使用、安全、隐私或发布 | 关键按钮不可点击、敏感信息泄漏 |
| P1 | 关键功能或跨风格一致性 | 同一状态在不同风格含义不同 |
| P2 | 普通统一与维护成本 | 同义组件重复、常用 Token 缺失 |
| P3 | 可选体验优化 | 更细的动画、装饰与次要效率 |

## 任务卡字段

每张任务卡必须包含：ID、领域、状态、维护角色、优先级、现状证据、目标、Why、影响、修改入口、依赖、风险、实施步骤、自动验证和人工验证。状态只能是“待评估、待实施、进行中、已阻塞、已完成、接受例外”。

## 当前任务卡

### UI-GAP-001：收口通用操作按钮

| 字段 | 内容 |
|---|---|
| 领域 / 优先级 / 状态 | 组件 / P2 / 待评估 |
| 维护角色 | 设计系统维护者、动态维护者、视频维护者 |
| 现状证据 | 源码存在至少三份 `ActionButton` 或相近实现，包括动态与视频详情领域；按压动画、图标容器和触摸区不同 |
| 目标 | 普通动作统一走 `AppButton`、`AppIconButton` 或一个共享语义入口；播放器/视频互动允许领域专用组件 |
| Why | 同名不同行为让初学者无法判断入口，也容易产生小于 48dp 的点击区 |
| 影响 | 动态卡、视频互动行、其他操作组 |
| 修改入口 | `AppPrimitiveComponents.kt`；各 feature 的 `ActionButton` |
| 依赖 / 风险 | 先分类语义；不能把“点赞计数操作”和“确认按钮”硬合并 |
| 实施步骤 | 列出调用点 → 按语义分组 → 确立共享入口 → 迁移普通场景 → 删除无调用旧实现 |
| 自动验证 | 结构测试、相关交互 policy 测试、48dp 规则测试 |
| 人工验证 | 三风格检查按下、选中、禁用、长文本与读屏名称 |

### UI-GAP-002：统一内容玻璃/卡片表面

| 字段 | 内容 |
|---|---|
| 领域 / 优先级 / 状态 | 卡片 / P2 / 待实施 |
| 维护角色 | 设计系统维护者 |
| 现状证据 | 搜索、消息、动态等存在至少三份 `GlassCard` 或同义外壳；已有 `ContentCardSurfacePolicy` 与 `AppCard` |
| 目标 | 一般卡面通过 `AppCard` + `ContentCardSurfacePolicy`，领域只提供内容和必要变体 |
| Why | 表面、边框、圆角和模糊降级应由主题统一 |
| 影响 | 列表性能、Miuix/Material/iOS 映射 |
| 修改入口 | `ContentCardSurfacePolicy`、`AppShapes`、各 feature `GlassCard` |
| 依赖 / 风险 | 动态转发卡、媒体封面等嵌套语义需保留；禁止卡中卡式装饰迁移 |
| 实施步骤 | 审计差异 → 定义变体 → 迁移通用卡 → 为领域例外写理由 |
| 自动验证 | `ContentCardSurfacePolicyTest` 与调用结构测试 |
| 人工验证 | 明/暗/AMOLED，关闭模糊，滚动列表不卡顿 |

### UI-GAP-003：统一错误与空状态

| 字段 | 内容 |
|---|---|
| 领域 / 优先级 / 状态 | 反馈 / P1 / 进行中（P005 试点完成） |
| 维护角色 | 设计系统维护者、各页面维护者 |
| 现状证据 | 旧 `LottieComponents.EmptyState/ErrorState` 与 feature 私有实现仍存在；P005 原先把分页失败写入整页 `error` |
| 目标 | 通过 `AppContentStateComponents.kt` 建立共享状态组件，明确标题、说明、主要恢复动作、次要动作与 PAGE/INLINE 变体 |
| Why | 错误必须可恢复，不能与空状态或未登录混淆 |
| 影响 | 全部网络页面与分页列表 |
| 修改入口 | `AppContentStateComponents.kt`、`SearchContentStatePolicy.kt`、`SearchViewModel.kt`、`SearchScreen.kt` |
| 依赖 / 风险 | 需保留页面已加载的可用数据；不能统一成整页遮挡 |
| 实施步骤 | 建立状态语义 → 设计共享 API → P005 试点 → 按阶段迁移消息和其他页面 |
| 自动验证 | `AppContentStatePolicyTest`、`SearchContentStatePolicyTest`、搜索 feature 测试、文档结构测试 |
| 人工验证 | 断网、重试、部分数据、分页失败、未登录逐项检查 |

**P005 试点证据（901a11954）**：已建立 `AppErrorState`/`AppEmptyState`，结果页按 body/footer policy 分离首次失败与分页失败；分页失败保留已有列表、页码和继续重试能力；热榜与搜索发现保留各自错误字段；系统返回和顶部返回先关闭建议/键盘。其余页面仍标记为待迁移，不能把本试点视为全局完成。

| 自动验证 | 值域与组件入口测试 |
| 人工验证 | 长用户名、1.3 倍字体、明暗主题、读屏状态 |

## 当前差距

本页列出首批已知差距，不代表完整缺陷清单。每次页面档案或人工验收发现新问题，应新增任务卡而不是修改目标规范去迁就现状。

## 验收方法

任务只有在自动验证通过、人工步骤有文字结果、目标代码入口唯一且旧入口已处理后才能标记完成；接受例外必须写期限或永久理由。
