## 初学者解释

响应式布局不是把手机界面整体放大。它根据“可用宽度”决定内容是单栏、双栏还是带侧栏，同时保持同一阅读顺序和功能。断点是布局改变的门槛，不等同于某台具体设备的型号。

## 规范要求

### 共享宽度等级

| 等级 | 本手册验收宽度 | 推荐结构 |
|---|---:|---|
| Compact | 360dp | 单栏、底部导航、弹层可占较大宽度 |
| Medium | 约 700dp | 更宽单栏、导航 Rail 或条件双栏 |
| Expanded | 840/1000dp | 侧栏、列表-详情双栏、内容最大宽度 |
| Media Extra Wide | 1600dp | 播放器与详情的媒体专用多区域布局 |

这些宽度是验收样本，不是要求所有页面共享一个硬编码判断。布局应优先读取当前窗口可用空间；设备旋转、分屏和折叠会让同一设备跨越等级。

### 页面已存在的特例

| 场景 | 当前源码事实 | 目标使用方式 |
|---|---|---|
| 设置 | 约 840dp 开始双栏 | 设置目录与详情并排，返回语义不能重复 |
| 搜索 | 600/840dp 等分段 | 控制结果列数、侧区和内容最大宽度 |
| 视频 | 无独立媒体断点，播放器/详情/评论按布局策略重排 | 播放器、详情和评论按空间重排 |

- **必须**在页面档案中说明任何特例断点的原因、结构变化和回退布局。
- **禁止**把某页面特例提升成全局 Token，除非至少三类页面验证共享语义。

### 稳定布局

- 固定格式元素（视频封面、播放器、按钮组、计数器）**必须**用 `aspectRatio`、明确 grid track、min/max 或稳定尺寸约束，不能由加载文字改变整体大小。
- 页面内容**必须**考虑系统栏、顶部栏、底栏、迷你播放器和输入法 inset。
- 列表**必须**使用稳定 key；刷新、分页和占位内容不应使已显示项目大幅跳动。
- 宽屏内容**应该**限制阅读宽度，不把长文本拉满 1600dp。
- 双栏布局**必须**定义主次宽度、分隔、焦点和返回行为。
- **禁止**在卡片内嵌套只为装饰的另一张卡；页面区块应使用留白或全宽带状结构。

### 信息顺序

```text
Compact
┌──────────────────┐
│ 顶部栏           │
├──────────────────┤
│ 主要内容         │
│ 次要内容         │
├──────────────────┤
│ 底部导航/迷你播放│
└──────────────────┘

Expanded（同一语义顺序）
┌──────┬───────────┬──────────┐
│ 导航 │ 主要内容  │ 次要详情 │
│ Rail │           │          │
└──────┴───────────┴──────────┘
```

宽屏可以把“后出现的次要内容”移到右侧，但不能把它提升成比主要内容更早的可访问阅读顺序。

### 返回与滚动

- Compact 的详情页面通常返回上一页；双栏中关闭详情应返回到列表选择状态，而不是退出整个功能。
- 系统返回、顶部返回与预测返回**必须**产生相同的最终导航结果。
- 切换宽度等级时，应尽量保留列表位置、选中项、搜索条件与播放状态。
- 顶部栏滚动行为必须在页面档案说明；禁止同一页出现两个争夺滚动的顶部栏。

## Compose 短示例

```kotlin
BoxWithConstraints {
    AppAdaptiveSplitLayout(
        useSplitLayout = maxWidth >= 840.dp,
        primaryContent = { listPane() },
        secondaryContent = { detailPane() },
    )
}
```

真实页面优先使用已有自适应策略与 `AppAdaptiveSplitLayout`，示例只解释思路。

## 代码映射

- 公共外壳：`AdaptiveChrome.kt` 中的 `AppScaffold`、`AppTopBar`
- 分栏：`AppSplitLayout.kt` 中的 `AppAdaptiveSplitLayout`
- 设备能力：`DeviceUiProfile`
- 设置宽屏外壳：`SettingsTabletShell.kt`、`SettingsTabletRouteShell.kt`
- 搜索布局：`SearchScreen.kt` 及其布局策略
- 视频布局：视频 detail/player 的 layout policy

## 当前差距

断点分散在多个页面和策略中，缺少一份“特例所有者”清单；部分固定尺寸仍由文字或加载内容撑开。宽度等级切换后的状态保存需要逐页验证。

## 验收方法

1. 用 360、700、840、1000、1600dp 可用宽度检查布局，不要求截图，只记录结构与结果。
2. 在每个宽度下检查最长中文标题、1.3 倍字体、加载/空/错误状态，无重叠和横向溢出。
3. 从 Compact 切到 Expanded 再切回，列表位置、选择、播放与输入尽量保留。
4. 双栏中分别验证顶部返回、系统返回和预测返回的最终页面。
