## 初学者解释

无障碍是让更多人能够完成同一个任务。读屏用户需要听到按钮名称和状态；动作不够精确的用户需要足够大的点击区；视力较弱的用户需要文字放大和颜色对比。它属于“功能是否完成”，不能等 UI 做完再补。

## 规范要求

### 触摸与手势

- 所有主要可点击目标**必须**至少 48dp × 48dp；视觉图标可以是 20/24dp。
- 相邻危险操作**应该**留出足够间距，避免误触。
- 任何长按、滑动、双击或拖动操作**必须**有可发现的普通点击或菜单替代方式。
- 播放器亮度/音量手势不能夺取系统返回、进度条或控制按钮事件。
- 禁用状态不能响应点击，也必须通过语义暴露 disabled。

### 名称、角色与状态

| 元素 | 必须提供 |
|---|---|
| 独立图标按钮 | 动作名称，如“返回”“收藏” |
| 开关 | 标题、已开启/已关闭、是否可用 |
| 选项卡 | 名称、选中状态、在集合中的位置 |
| 进度 | 当前值或“不确定进度”的语义 |
| 图片 | 有业务信息时提供描述；纯装饰设为 `null` |
| 视频卡 | 合并或有序暴露标题、作者和关键状态，避免逐字碎片化 |
| 错误 | 错误内容与恢复操作 |

- **禁止**给整个屏幕的所有图标都机械添加重复描述。
- **禁止**把可点击父容器和内部文字分别暴露成两个相同动作。
- **必须**让当前选择、播放/暂停、关注/已关注等状态可被读屏识别，不能只改变颜色。

### 焦点和阅读顺序

- 阅读顺序**必须**符合信息顺序：标题、主要内容、次要内容、操作。
- 弹窗和底部面板打开时，焦点进入弹层；关闭后尽量返回触发元素。
- 双栏布局不能因为视觉位置改变而先读次要详情再读主要列表。
- 列表刷新不应无故把读屏焦点移到顶部。
- 验证码、密码和隐私数据必须使用正确语义，不能被普通日志或无关界面读出。

### 文字、颜色与缩放

- 文本必须支持系统字体缩放；1.3 倍时主要任务完整可操作。
- 正常正文目标对比度至少 4.5:1，大号或粗体文字至少 3:1；图形控件与焦点边界至少 3:1。
- 颜色不能是唯一状态编码。错误还要有文字/图标，选中还要有形状/标记/语义。
- 动态背景或封面上的文字必须使用稳定遮罩或独立表面，不能依赖某张图片恰好较暗。

### 动效与媒体

- 尊重系统减少动画设置；详见[动效与效果](06_MOTION_EFFECTS.md)。
- 自动播放内容必须可暂停；声音不应在无明确用户动作时突然出现。
- 播放控制必须有明确名称，播放与暂停不能共享一个过时的描述。
- 直播、音频和后台播放状态应与系统媒体控制语义一致。

## Compose 短示例

```kotlin
AppIconButton(
    onClick = onToggleFavorite,
    icon = icon,
    contentDescription = if (favorited) "取消收藏" else "收藏",
    modifier = Modifier.minimumInteractiveComponentSize()
)
```

动作名称随状态变化，父组件保证触摸范围。

## 代码映射

- 最小触摸目标：`AppChromeSizeTokens.MinimumTouchTarget`
- 公共图标按钮：`AppPrimitiveComponents.kt` 中的 `AppIconButton`
- 设置项：`AppPreferenceComponents.kt`
- Compose 语义：`Modifier.semantics`、`contentDescription`、`stateDescription`
- 本地返回：`LocalNavigationBackHandler`

## 当前差距

部分独立点击图标仍可能使用 `contentDescription = null`；部分领域操作用小视觉容器直接 `clickable`，需要验证父点击区是否达到 48dp。颜色对比度目前没有覆盖所有用户自定义主题角色。

## 验收方法

1. 使用 Android TalkBack 依次完成首页进入视频、播放/暂停、收藏、返回；记录读出名称和最终结果。
2. 开启大字体后检查首页卡片、搜索、设置、弹窗和播放器控制，无文字遮挡关键操作。
3. 使用触摸目标检查或布局审查确认所有动作至少 48dp。
4. 关闭颜色信息或使用灰度思路检查，选中、错误、禁用和播放状态仍可判断。
